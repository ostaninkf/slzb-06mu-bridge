# Своя прошивка моста SLZB-06MU (ESP-IDF, без Arduino)

[English](README.md) · Русский

Замена SLZB-OS на мосту второй Zigbee-сети («Склад», насос). Причина —
разбор штатной прошивки в `~/Claude/slzb/LOG.md`: задача, обслуживающая
радио, периодически перестаёт вычитывать UART, данные копятся в буфере
драйвера и выходят залпом, NCP к этому времени успевает выбрать таймауты и
рвёт соединение.

## Что сделано иначе

| | SLZB-OS | здесь |
|---|---|---|
| Чтение UART | приостанавливается, пока группа событий не примет строго определённое значение | безусловно, в каждом обороте цикла |
| Управление потоком | `HW Flow: off` — RTS выведен как статичный GPIO, вход CTS выключен | аппаратный RTS включён: не успеваем — NCP тормозится на физическом уровне |
| Блокирующие вызовы | есть, без таймаутов | нет ни одного: `poll` с таймаутом 5 мс, неблокирующие сокет и UART |
| Task watchdog | задачи не подписаны | подписаны все свои задачи, при зависании — паника и перезагрузка |
| Подвисший TCP-клиент | может удерживать радио | новое соединение всегда вытесняет старое |
| Диагностика | лог в кольцевой буфер | счётчики байт/обрывов/переполнений в `/status`, отчёт в консоль раз в 30 с |

Всё, что не нужно мосту (BLE, Wi-Fi, MQTT, музыка, аддоны, веб-панель на
полтора мегабайта), не собирается вовсе: образ — 462 КБ против 4 МБ.


## Что умеет

Всё настраивается через веб и хранится в NVS — в прошивке нет ни одного зашитого
адреса, пароля или порта.

- **Мост радио → сеть**: TCP-порт, скорость UART, управление потоком
  (выключено / RTS / RTS+CTS) — всё меняется без пересборки.
- **Режим USB**: радио отдаётся не в сеть, а в USB-CDC — мост можно воткнуть
  прямо в машину с Z2M. В этом режиме консоль занята данными, журнал остаётся
  только в syslog.
- **Сеть**: DHCP или статический адрес, имя хоста, DNS, свой MAC при
  необходимости. Wi-Fi поднимается **только как резерв**, когда пропал линк по
  витой паре; если сети нет вовсе — через минуту включается точка доступа, чтобы
  мост можно было настроить, не разбирая корпус. Есть mDNS и синхронизация
  времени.
- **Прошивка радиомодуля через мост**: файл `.gbl` заливается из браузера в
  Gecko Bootloader по XMODEM. Наружу мост при этом не ходит — в отличие от
  штатной прошивки, которая тянула образ с сервера производителя.
- **Обновление самого моста** по сети, в свободный OTA-слот.
- **MQTT**: прошивка сама публикует состояние с HA-discovery — аптайм, клиент на
  радио, обрывы, переполнения буфера, байты в обе стороны, температура чипа.
  Внешний сборщик больше не нужен.
- **Syslog** по UDP: журнал переживает перезагрузку моста, оставаясь на чужой
  машине.
- **Индикация**: светодиоды можно погасить совсем или по ночам, по расписанию.
- **Кнопка**: короткое нажатие — сброс радио, 5 секунд — перезагрузка моста,
  15 секунд — сброс настроек к заводским.

Не перенесено из штатной прошивки то, чего на этой плате нет или что уводит
мост в интернет: второе радио и CC1101, 4G и Z-Wave, Thread/OTBR, BLE-прокси,
VPN, зуммер с мелодиями и подсветка Ambilight (это функции старших моделей
серии — Ultima и SLW09U), а также автообновление с серверов производителя.

## Железо

Распиновка — `main/board.h`. Снята с работающего моста через JTAG
(GPIO-матрица + IO_MUX) и сверена с официальным описанием SMLIGHT:
`github.com/smlight-tech/slzb-esphome`, `hw_defs/06xu/r1_73.yaml`.

- W5500 на SPI3: SCLK 42, MOSI 39, MISO 41, CS 2, INT 38, RST 40
- EFR32MG21 (NCP) на UART2: TX 17, RX 18, RTS 14, CTS 15, RST 21, boot 16
- LED 46 и 45, кнопка 0, RJ45-подсветка 1 — все инверсные
- флеш 16 МБ DIO 80 МГц, PSRAM quad 80 МГц (проверено по заголовку штатного загрузчика)

MAC-адрес не зашит: он выводится из базового eFuse-адреса через
`esp_derive_local_mac()` — ровно так его получала штатная прошивка на Arduino.
Поэтому после замены прошивки мост остаётся под прежним адресом и резервация
DHCP выдаёт тот же IP. Нужен другой адрес — положи рядом `main/local_config.h`
с `#define ETH_MAC_OVERRIDE { ... }` (в репозиторий он не попадает).

## Сборка и заливка

```sh
./build.sh                      # сборка в docker espressif/idf:release-v5.4
./flash.sh /dev/ttyACM0         # снимет дамп флеша в backup/, затем зальёт
./ota.sh <адрес-моста>          # последующие обновления — по сети
./restore.sh ../slzb/flash-dump-20260914-1646.bin   # вернуть штатную SLZB-OS
```

`flash.sh` сначала снимает полный 16-мегабайтный дамп: только так возвращаются
настройки и ключи сети Zigbee. Уже снятый дамп от 14.09.2026 лежит в
`~/Claude/slzb/flash-dump-20260914-1646.bin` (md5 b22e1cc5…).

## Что мост отдаёт

- TCP `:6638` — поток NCP, как ждёт zigbee-herdsman (`tcp://<адрес-моста>:6638`)
- HTTP `:80` — страница со счётчиками, `/status` (JSON), `/update` (OTA),
  `/ncp/reset`, `/reboot`
- кнопка: короткое нажатие — сброс NCP, удержание 5 с — перезагрузка моста
- консоль — на встроенный USB-JTAG (UART0 не занят)

## Состояние

Работает на живом мосту с 14.09.2026: Ethernet поднимается, Z2M обменивается
с NCP, OTA по сети проверена (мост сам перезагрузился и поднялся с раздела
`ota_1`, сверено по otadata).

CTS по умолчанию выключен: включать только после проверки, что радиомодуль
собран с аппаратным управлением потоком — иначе передача встанет намертво.
Набор из раздела «Что умеет» собран и проверен компилятором, но на живом мосту
пока работает предыдущая версия — заливка по готовности.
